Security

How we protect your data

This page describes the technical and organisational measures pursuant to Art. 32 GDPR – verifiable and without marketing promises.

Honesty before badges: We only list measures here that are actually in place. Information about certifications such as ISO 27001 or TISAX may only appear once a valid certificate exists – otherwise there is a risk of warnings under competition law.

Protection at every level

Encryption

  • TLS 1.3 for every connection, HTTP is redirected to HTTPS
  • HSTS with a long duration and subdomains
  • AES-256 for database, file storage and backups
  • Key management separate from the data

Access and identity

  • Two-factor authentication, mandatory for company accounts
  • Password check according to BSI recommendation, stored as an Argon2id hash
  • Lock after five failed attempts, graduated waiting times
  • Automatic sign-out after 15 minutes of inactivity

Permissions

  • Role concept based on the principle of least privilege
  • Contact details only visible after mutual approval
  • Tenant separation at database level
  • Access by staff only with a reason and a log

Operation and location

  • Data centres exclusively in the EU
  • Daily backup, encrypted, 30 days retention
  • Restore tested at least every six months
  • Data processing agreements with all service providers

Logging

  • Every profile access is recorded with time and reason
  • Logs can be viewed by data subjects in their account
  • Tamper-proof storage, separate from the application system
  • Automatic alert for unusual access patterns

Application security

  • Strict Content Security Policy without unsafe-inline
  • Output only as text, so there is no path for XSS
  • CSRF token for every modifying request
  • Dependencies are automatically checked for vulnerabilities
In detail

Why this site does not load third-party content

Every embedded third-party resource is a potential attack path and at the same time transmits the visitor's IP address to third parties. That is why fonts, icons and scripts are hosted on our own server.

The rule is not just claimed but enforced by the browser: the following policy prohibits loading external sources and blocks scripts injected into page content.

Content-Security-Policy:
default-src 'self';
script-src 'self';
style-src 'self';
img-src 'self' data:;
connect-src 'self';
form-action 'self';

base-uri 'none';
object-src 'none';

Also set as HTTP headers: Strict-Transport-Security, X-Content-Type-Options, Referrer-Policy, Permissions-Policy and Cross-Origin-Opener-Policy. The finished server configuration is included with the application.

Handling security incidents

  1. Detect: automatic monitoring, external reports, regular review of logs.
  2. Contain: block affected access, end sessions, rotate keys.
  3. Report: if there is a risk to data subjects, notification of the supervisory authority within 72 hours (Art. 33 GDPR); if the risk is high, data subjects are also notified (Art. 34 GDPR).
  4. Follow up: root cause analysis, measures, written report in the record of processing activities.

Before going live

What still needs to be implemented on the server

This application is a prototype without a backend. The following points cannot be implemented in the browser and must be handled on the server.

Technical

  • Serve security headers via the web server (the file assets/security-headers.conf is included)
  • Session cookies with HttpOnly, Secure and SameSite=Strict
  • Rate limiting per account and IP address, real TOTP verification
  • Server-side validation of all inputs and file uploads
  • Virus scanning of uploaded references, storage outside the web directory

Organisational

  • Create a record of processing activities (Art. 30 GDPR)
  • Data protection impact assessment for applicant matching
  • Data processing agreements with hosting and translation service
  • Check the licence under the German Temporary Employment Act, if applicable
  • Staff training, confidentiality undertaking
